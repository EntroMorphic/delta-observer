# Same-history arithmetic causal fork v1

Frozen before this diagnostic. No training or model selection. Use all forty
exposed arithmetic cases and ordinary seeds 0, 1, 2 from retention-transfer v2.
Donors are the already recorded native and ordinary generations from arithmetic
access v1, under both original and reasoning-request prompts.

## Registered factorial

For each seed, task and prompt mode (original / fixed reasoning request):

- Prefix source: empty, native generation, same-seed ordinary generation.
- Recipient: all adapters on, all adapters scale-zero.
- Every recipient gets **exactly the same complete token history** for each
  prefix; reconstruct all activations from scratch. Do not carry a donor cache
  or mix cache states. Identical tokens are not identical hidden states.

Extract donor prefixes by retaining at most 16 generated tokens, stopping
**before** the token overlapping the start of the first Unicode numeric
character or English cardinal-number word (zero through nineteen,
tens twenty through ninety, hundred, thousand, million, billion, trillion,
dozen). Also stop before any special/control token. Do not inspect expected
answers, numerical correctness, source success or model preference when choosing
prefix length. No native worked values, computed numbers or final-answer tokens
are provided. Ordinal/discourse words such as `First` are not cardinal numbers.
Verbal context can still influence routing; it is the intended intervention.
Detect the first numeric/cardinal boundary in the full decoded donor, but supply
only tokens ending before that boundary. This prevents a split cardinal such
as `twen` + `ty` leaking a partial number word, even at the token cap.

Keep exact donor token IDs, not decode/re-encoded text. Record source file hash,
source arm/condition/case, prefix IDs/text, rejected next-token text and stop
reason. Empty or identical prefixes are retained, not replaced. Never treat
repeated histories as independent evidence: cache identical executions within
each seed and record explicit aliases and unique-execution runtimes.

Greedy, pinned LFM2.5-350M, FP16 base/FP32 adapters on accelerator, same native
tokenizer. Total assistant output budget 192 tokens **including** supplied
prefix. EOS and generation settings unchanged otherwise. Each execution also
records a separate full-history first-token forward, with full next-token
softmax CPU copy for paired readouts. No answer-dependent decoder constraint.

## Controls and measurements

- Empty-prefix adapter-on/off must reproduce stored original/reasoning
  generations token-for-token. Abort if these original engineering controls
  fail. For each nonempty prefix, compare donor-recipient self-continuation
  to its stored donor remainder. Self-replay agreement is **measured**, not
  assumed: re-prefill can differ numerically from incremental cached execution.
  Preserve any mismatches; do not claim replay identity when they occur.
- For every off/on pair assert input-token equality and record first-token
  top-1, cross-probabilities, JS divergence, EOS/numeric-support mass, and first
  continuation divergence. These are same-history token-distribution effects,
  not state swaps, unique circuit localization or capability scores.
- Full assistant response is donor prefix + generated continuation. Use unchanged
  original exact and narrow boxed-content scores. Also save continuation scores
  only as labeled conditionals, never native compliance after stripping text.
- Report all content gains/losses vs own empty-prefix run and paired on/off
  regressions by ID, all seeds/prompt modes/donors, self-replay/parity failures,
  duplicate-history counts, generated tokens and actual unique runtimes.
- Prefixes are generated by models but filtered only by a fixed lexical rule.
  This rejects explicit numbers, not every possible semantic clue. Do not call
  these an independently blinded evaluation or a proof of zero semantic leakage.

## Interpretation

If a native safe prefix recovers adapter-on content without turning adapters
off, useful behavior is conditionally accessible after that nonnumeric history.
If on/off predictions differ with identical histories, the effect is not solely
due to previously generated different tokens. This does not distinguish an
altered computed state from an altered readout of a state; further state-level
interventions would be needed. No recovery does not prove irreversible loss.
Native off control is not an improvement or speed claim. No best-seed selection,
universal root cause, or promoted adapter follows from an aggregate gain.
